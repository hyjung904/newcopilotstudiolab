# 데이터 분석 및 DOCX 보고서 생성 Skill

## 목적

사용자가 제공한 하나 이상의 CSV 또는 표 형식 데이터를 분석하여 다음 결과물을 생성한다.

1. 데이터 구조와 품질 확인
2. 핵심 지표 계산
3. 데이터에 적합한 차트 생성
4. 차트 기반 분석 및 시사점 작성
5. 차트가 포함된 전문적인 DOCX 보고서 생성

이 Skill은 특정 산업이나 고정된 컬럼명에 종속되지 않는다.

---

## 실행 단계

### Step 1. 입력 데이터 확인

모든 파일을 읽고 다음을 확인한다.

* 파일명
* 컬럼명
* 행 수
* 날짜 또는 기간 컬럼
* 비교 대상 컬럼
* 숫자형 측정값
* 범주형 컬럼
* 단위
* 결측값과 중복값

파일명만으로 내용을 판단하지 말고 실제 데이터를 기준으로 분석한다.

---

### Step 2. 분석 기준 결정

사용자의 요청과 데이터 구조를 바탕으로 다음을 결정한다.

* 무엇을 비교할지
* 어떤 기간을 분석할지
* 어떤 지표가 중요한지
* 어떤 범주로 세분화할지

사용자가 구체적인 분석 기준을 지정하지 않은 경우, 데이터에서 가장 의미 있는 비교 기준과 지표를 선택한다.

---

### Step 3. 데이터 검증 및 정리

다음을 확인한다.

* 숫자 또는 날짜 형식 오류
* 누락된 값
* 중복된 행
* 비정상적으로 크거나 작은 값
* 서로 다른 단위
* 서로 다른 집계 수준

명확한 형식 오류는 수정할 수 있지만, 누락된 값을 임의로 생성하지 않는다.

서로 다른 단위나 집계 수준의 데이터는 직접 합산하지 않는다.

---

### Step 4. 핵심 지표 계산

데이터에 적합한 핵심 지표를 5~10개 선정한다.

예:

* Total
* Average
* Growth Rate
* Percentage Change
* Category Share
* Margin
* Completion Rate
* Utilisation Rate
* Top Performer
* Lowest Performer

계산식에 필요한 값이 명확한 경우에만 비율이나 성장률을 계산한다.

---

### Step 5. 차트 선택 및 생성

데이터 구조와 분석 목적에 따라 4~6개의 차트를 생성한다.

#### Line Chart

다음 경우에 사용한다.

* 월별, 분기별, 연도별 추세
* 시간에 따른 증가 또는 감소
* 여러 대상의 추세 비교

제목 예:

* `Revenue Trend`
* `Monthly Performance Trend`
* `Growth Trend by Entity`

#### Bar Chart

다음 경우에 사용한다.

* 대상별 실적 비교
* 범주별 값 비교
* 순위 또는 Top N 분석

제목 예:

* `Performance Comparison`
* `Sales by Region`
* `Top Products by Revenue`

범주가 많은 경우 Horizontal Bar Chart를 사용한다.

#### Grouped 또는 Stacked Bar Chart

다음 경우에 사용한다.

* 동일 범주에서 여러 대상 비교
* 실제값과 목표값 비교
* 전체 규모와 내부 구성 비교

제목 예:

* `Actual vs. Target`
* `Category Performance by Entity`
* `Revenue Mix by Region`

#### Pie 또는 Donut Chart

다음 조건에서만 사용한다.

* 단일 시점의 구성비
* 범주가 2~6개
* 항목 합계가 의미 있는 전체를 구성함

#### Scatter Chart

다음 경우에 사용한다.

* 두 수치형 변수 간 관계
* 효율성 비교
* 이상값 확인

제목 예:

* `Cost vs. Revenue`
* `Inventory vs. Sales`
* `Processing Time vs. Satisfaction`

상관관계를 인과관계로 표현하지 않는다.

---

## 차트 작성 규칙

1. 차트 제목은 영어로 작성할 수 있다.
2. 축 제목과 단위를 표시한다.
3. 동일한 비교 대상은 차트마다 같은 색상 또는 스타일을 사용한다.
4. 금액, 비율, 수량의 단위를 일관되게 표시한다.
5. 시간 데이터는 시간 순서대로 정렬한다.
6. 과도한 색상, 3D 효과 및 불필요한 장식을 사용하지 않는다.
7. 원본 데이터에 없는 값을 차트에 추가하지 않는다.
8. 모든 차트는 DOCX에 삽입 가능한 이미지로 생성한다.

---

## 차트 분석 규칙

각 차트 아래에 2~4개의 핵심 분석 내용을 작성한다.

다음 구조를 활용한다.

### Observation

데이터에서 직접 확인되는 사실

### Interpretation

해당 추세나 차이가 의미하는 내용

### Implication

업무, 운영, 재무 또는 전략 측면의 시사점

단순히 차트의 숫자를 반복하지 않는다.

다음을 중심으로 분석한다.

* 증가 또는 감소 추세
* 대상 간 격차
* 최고 및 최저 성과
* 주요 기여 범주
* 변동성
* 이상값
* 기회 요인
* 위험 요인

데이터에 없는 원인을 임의로 추정하지 않는다.

## DOCX 보고서 구성

데이터에 적합한 섹션만 선택하여 보고서를 작성한다.

### 표지

* 보고서 제목
* 분석 대상
* 분석 기간
* 작성일

### 1. Executive Summary

다음을 간결하게 요약한다.

* 주요 결과
* 가장 중요한 변화
* 최고 및 최저 성과
* 핵심 기회
* 핵심 위험
* 최종 시사점

### 2. Scope and Methodology

* 사용한 파일
* 분석 대상과 기간
* 데이터 단위
* 집계 및 계산 방법
* 분석 제한사항

### 3. Data Overview

* 데이터 규모
* 주요 컬럼
* 비교 대상
* 기간
* 데이터 품질 상태

### 4. Key Performance Indicators

선정한 핵심 KPI를 표로 비교한다.

### 5. Trend Analysis

시간 데이터가 있는 경우 포함한다.

* 추세 차트
* 성장 또는 감소
* 변동성
* 주요 기간 분석

### 6. Comparative Analysis

비교 대상이 여러 개인 경우 포함한다.

* 대상별 성과
* 순위
* 격차
* 강점과 약점

### 7. Category Analysis

범주형 데이터가 있는 경우 포함한다.

* 주요 기여 범주
* 구성비
* 저성과 범주
* 집중도

### 8. Risks and Opportunities

데이터에서 확인된 기회와 위험을 정리한다.

### 9. Conclusion and Recommendations

* 종합 분석 결과
* 핵심 시사점
* 우선적으로 확인할 지표
* 데이터에 근거한 실행 제안

### Appendix. Data Quality Notes

* 결측값
* 중복값
* 이상값
* 제외된 데이터
* 분석 제한사항

## 문서 작성 규칙

1. 보고서 본문은 한국어로 작성한다.
2. 차트 제목과 일반적인 KPI 명칭은 영어를 사용할 수 있다.
3. 전문적이고 객관적인 보고서 문체를 사용한다.
4. 각 차트는 관련 분석 섹션에 삽입한다.
5. 차트 바로 아래에 분석과 시사점을 작성한다.
6. 표와 차트의 수치가 본문과 일치하도록 검증한다.
7. 데이터에 없는 사실이나 외부 원인을 임의로 추가하지 않는다.
8. 표지, 목차, 페이지 번호를 포함한다.
9. 표와 차트가 페이지 밖으로 잘리지 않도록 구성한다.
10. 최종 결과물은 DOCX 파일로 제공한다.

## 최종 검토

보고서 생성 전에 다음을 확인한다.

* 모든 입력 파일을 확인했는가
* 비교 대상과 분석 기간이 명확한가
* 데이터 단위가 일관적인가
* 계산된 KPI가 데이터 의미에 적합한가

* 차트와 본문의 수치가 일치하는가
* 데이터에 없는 내용을 작성하지 않았는가
* Executive Summary와 Conclusion의 결론이 일치하는가
* DOCX 문서가 전문적인 형식으로 작성되었는가

## Tool 연결 

**해당 에이전트는 Tool 연결이 필요하지 않습니다.** 
Modern Copilot Studio (New Experience)에서는 Tool 연결 없이도 CSV 파일을 업로드하고 분석할 수 있습니다. 데이터 분석에 필요한 주요 Python 라이브러리가 기본적으로 포함되어 있으므로, 별도의 패키지 설치(pip install) 없이 바로 사용할 수 있습니다. 

이번 실습에서 사용한 주요 라이브러리는 다음과 같습니다. : 

- **zipfile :** Python 표준 라이브러리로 ZIP 파일의 압축 해제 및 압축 생성 기능을 제공합니다. 업로드된 ZIP 파일에서 CSV 데이터를 추출하는 데 사용되었습니다.
- **pandas :** 표 형식 데이터를 처리하기 위한 대표적인 데이터 분석 라이브러리입니다. CSV 파일을 읽고, 여러 데이터를 병합하며, 집계(GroupBy), KPI 계산 및 데이터 전처리에 사용되었습니다.
- **numpy :** 수치 계산 라이브러리로 배열 연산과 차트 생성 시 필요한 위치 계산 및 수학 연산에 활용되었습니다.
- **matplotlib :** 데이터 시각화를 위한 라이브러리입니다. Line Chart, Bar Chart 등 다양한 형태의 차트를 생성하여 PNG 이미지로 저장하는 데 사용되었습니다. 서버 환경에서는 GUI가 없는 환경에서도 이미지를 생성할 수 있도록 Agg Backend를 사용합니다.
- **python-docx :** Microsoft Word(.docx) 문서를 생성하는 라이브러리입니다. 제목, 표, 문단, 이미지, 차트 등을 삽입하여 전문적인 보고서를 자동으로 생성하는 데 사용되었습니다.

이러한 방식은 Modern Copilot Studio의 Agent Sandbox를 활용하는 대표적인 시나리오입니다. Agent는 격리된 Linux/Python Sandbox에서 코드를 실행하여 데이터 분석, 계산, 파싱, 차트 생성 및 문서 생성을 수행합니다. 

> Q. 그렇다면 언제 Tool(Outlook, SharePoint, Teams 등)을 연결해야 하나요? Code Execution과의 차이점은 무엇인가요? 

A. **Tool은** Outlook, Teams, SharePoint, Dataverse와 같은 **외부 서비스와 연결하여 데이터를 가져오거나 작업을 수행** 할 때 사용합니다. 예를 들어 메일을 조회하거나 발송하고, Teams 메시지를 보내거나, SharePoint 파일을 읽고 저장하는 작업은 Tool이 담당합니다.

반면 **Code Execution(Agent Sandbox)** 은 가져온 데이터나 사용자가 업로드한 파일을 처리하는 기능입니다. 예를 들어 데이터 분석, 계산, 파일 변환, 차트 생성, 보고서(DOCX) 생성과 같은 작업을 수행합니다.

쉽게 말하면 Tool은 데이터를 가져오고 저장하는 역할, Code Execution은 데이터를 분석하고 결과물을 만드는 역할입니다. 실제 업무에서는 두 기능을 함께 사용하는 경우가 가장 많습니다.
